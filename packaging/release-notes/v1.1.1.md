Two fixes from the marketplace security review: clicks act on the window the widget names, and an icon given as a file path is loaded only when it is a regular file.

**Update** with `omarchy plugin update crmne.active-window`, or install with `omarchy plugin add https://github.com/crmne/omarchy-active-window.git --enable --yes`.

## Fixed

- **Middle click closes the window the label shows.** The title came from Hyprland's active window, while clicks went to the active Wayland window. While focus was moving the two could differ, so a middle click could close a window other than the one named. Left and middle clicks now act on the window whose title the widget shows, and do nothing if that window cannot be reached. By @crmne.
- **Icon files are checked before they load.** A desktop entry can name its icon by path, and that path was handed straight to the shell's image loader, so a special file there could hold up other icons. The widget now loads an icon path only once it is a regular file, and shows the generic application icon until then. By @crmne.

## Known limitations

- Following Omarchy's animation switch needs Omarchy 4.5 or later. On earlier versions, only the widget's own **Animate width changes** setting turns the animation off.
